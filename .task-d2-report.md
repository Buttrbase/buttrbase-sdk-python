## What Was Done

1. **Dependency**: `PyJWT[crypto]>=2.8` added as optional `[crypto]` extra in
   `pyproject.toml`. Installed into the repo's `.venv` during development.
   Core dep list (`requests>=2.28`) unchanged.

2. **`Verifier` class** added to `src/buttrbase/verify.py`:
   - Constructor: `Verifier(jwks_url, issuer, audience=None)` — mirrors Rust
     SDK's `VerifierConfig { jwks_url, issuer, audience: Option }`.
   - `verify_token(token: str) -> Claims` — calls `PyJWKClient.get_signing_key_from_jwt`,
     then `jwt.decode` with RS256 + issuer validation (audience optional), maps
     payload through existing `Claims.from_dict` — no duplication of dataclasses.
   - `verify_bearer(authorization: str) -> TokenPrincipal` — strips `Bearer ` prefix,
     calls `verify_token`, returns `TokenPrincipal.from_claims(claims)`.
   - `issuer` and `audience` read-only properties.
   - `PyJWKClient` imported at module level (inside a try/except) so it is
     patchable at `buttrbase.verify.PyJWKClient` in tests.

3. **`VerifierError`** — single exception class raised on all failure modes
   (bad signature, expired, wrong issuer, wrong audience, JWKS fetch failure,
   missing Bearer prefix).

4. **Exports**: Both `Verifier` and `VerifierError` added to `src/buttrbase/__init__.py`
   `__all__` and the import line.

5. **Tests** (`tests/test_verifier.py`, 22 tests):
   - RSA-2048 keypair generated locally with `cryptography`; JWKS dict built
     from public-key `n`/`e`; tokens signed with `jwt.encode`.
   - `PyJWKClient` monkeypatched via `unittest.mock.patch` at
     `buttrbase.verify.PyJWKClient` — zero network calls.
   - Happy path: `verify_token` returns `Claims` with data envelope; `verify_bearer`
     returns `TokenPrincipal` with roles/email/scopes.
   - Negative: bad signature (different keypair), expired token (`exp_offset=-3600`),
     wrong issuer, wrong audience, missing/wrong Bearer prefix, JWKS lookup exception.
   - End-to-end: real RSA sig + full enriched `Claims → TokenPrincipal` path.

6. **CHANGELOG** and **README** updated documenting 0.6.0 with install instructions,
   constructor signature, and usage examples for both `verify_token` and `verify_bearer`.

## Concerns

None. The `audience=None` semantic (skip aud validation) correctly matches the Rust
SDK's comment that buttrbase access tokens do not carry a stable per-application `aud`
in most flows. The `PyJWT[crypto]` optional-extra pattern keeps the zero-dependency
core intact for consumers who only need offline payload parsing.
